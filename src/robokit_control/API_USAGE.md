# Ubuntu 22.04 / ROS 2 Humble 底盘速度控制

这组脚本依据本次提供的 Robokit 文档实现 API 2010。动捕接入和目标点闭环控制属于后续接入部分。

## 1. 电脑怎样把命令发到底盘

```text
Ubuntu 电脑                         底盘控制器
192.168.1.100/24                    192.168.1.200/24
Python socket  ─── TCP 连接 ──────> 19205 端口
               ─── 头部 + JSON ──> 解析速度并执行
               <── 头部 + JSON ─── 返回执行请求的结果
```

这里的 IP 是示例，需要替换为实际地址。网线直连、交换机、允许设备互通的路由器都可以。电脑与底盘处于同一子网时最容易调通，两者的 IP 必须不同。跨子网时需要可达的路由。端口 19205 是底盘控制 API 的服务端口，电脑的客户端源端口由操作系统选择。

先查看 Ubuntu 的有线网卡及地址，再确认底盘的实际 IP。若电脑网段不同，可以在 Ubuntu 的“设置 → 网络 → 有线 → IPv4”中配置同网段的空闲地址和掩码。网线直连的专用连接通常无需默认网关。

```bash
ip -br addr
ip route get 192.168.1.200
ping -c 3 192.168.1.200
nc -vz -w 2 192.168.1.200 19205
```

`nc` 由 `netcat-openbsd` 提供。最后一条仅检测 TCP 连接。机器人可能关闭 ICMP，因此 ping 结果需要结合端口连接结果判断。检查网卡、网线、底盘 IP、接口服务和防火墙可以定位连接失败。

## 2. API 报文

请求使用控制端口 `19205`，请求编号 `2010 / 0x07DA`，响应编号 `12010 / 0x2EEA`。

| 字段 | 字节数 | 本实现 |
| --- | --- | --- |
| 同步头 | 1 | 0x5A |
| 版本 | 1 | 默认 1，RBK3.4 使用 1，RBK3.5 使用 2 |
| 序号 | 2 | 自动递增，响应序号应一致 |
| 数据区长度 | 4 | UTF-8 JSON 字节数 |
| API 编号 | 2 | 2010 |
| 内部区域 | 6 | 全零，普通无压缩请求 |

头部总长 16 字节。按照截图的十六进制示例，多字节整数使用大端序，Python 格式为 `!BBHIH6s`。程序使用 `sendall()`，分别完整读取响应头和响应体，处理 TCP 分段，并检查序号、响应类型和返回码。

JSON 数据示例

```json
{"vx":0.05,"vy":0.0,"w":0.0,"duration":300}
```

`vx`、`vy` 是机器人自身坐标系中的速度，单位 m/s。`w` 单位 rad/s，逆时针为正。实际 x/y 轴方向需要结合底盘坐标定义确认。横移需要底盘具备相应运动能力。

`duration` 单位 ms，文档注明 0 会持续保持速度。本脚本选择有限的 300 ms，持续运动时重复刷新。到期行为及实际减速停车过程仍需在底盘上验证。文档中参数配置给出的时间范围为 0..5000 ms，本脚本采用 1..5000 ms。

`ret_code` 为 0 或缺省表示请求没有报错，响应体也允许为空。是否到达目标位置需要后续用动捕反馈判断。API 2010 会取消机器人当前导航任务，零速度也使用这个接口。

## 3. 直接在 Ubuntu 发送速度

解压后进入 `robokit_control` 目录。直接调用只依赖 Python 标准库。

```bash
cd robokit_control
python3 robokit_tcp.py --host 192.168.1.200
```

这条命令发送零速度并读取响应。若底盘运行 RBK3.5，所有命令都添加 `--version 2`。默认版本 1 与最初速度 API 截图中的示例一致，实际固件版本仍需确认。

沿机器人 x 正方向以 0.05 m/s 发送速度约 2 秒，然后主动发送零速度

```bash
python3 robokit_tcp.py --host 192.168.1.200 --vx 0.05 --seconds 2
```

横移和旋转的调用方式

```bash
python3 robokit_tcp.py --host 192.168.1.200 --vy 0.05 --seconds 2
python3 robokit_tcp.py --host 192.168.1.200 --w 0.1 --seconds 2
```

省略 `--seconds` 时只发送一次有限时长速度，等待该时长后主动发送零速度。`Ctrl+C` 和异常退出也会尝试发送零速度。网络中断时，程序会报告停止命令是否确认送达，底盘端的有限运动时长负责限制最后一条速度的持续时间。

默认按约 20 Hz 刷新，每次请求等待响应。实际频率受 TCP 往返时延影响，可通过 `--rate` 调整。`--timeout` 默认 0.2 秒，限制一次请求发送及响应读取时间，建立连接另有同样的超时。通信异常后终止本次运动，清理阶段仅尝试发送零速度。

首次实机测试使用上面的低速短时命令，逐一确认 vx、vy、w 的方向以及停止行为。

## 4. ROS 2 /cmd_vel 桥接

两个 Python 文件放在同一个目录。当前按脚本直接运行，使用 Ubuntu 系统 Python 和已经安装的 Humble 环境。

终端 1

```bash
source /opt/ros/humble/setup.bash
python3 robokit_cmd_vel.py --ros-args -p robot_ip:=192.168.1.200
```

RBK3.5 使用

```bash
python3 robokit_cmd_vel.py --ros-args -p robot_ip:=192.168.1.200 -p protocol_version:=2
```

终端 2 持续发布机器人坐标系速度

```bash
source /opt/ros/humble/setup.bash
ros2 topic pub --rate 20 /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

按 `Ctrl+C` 停止终端 2 发布。桥接节点在接收超时后下发零速度。也可主动发布

```bash
ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist \
  '{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}'
```

主要参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| robot_ip | 空 | 必须填写 |
| port | 19205 | 控制 API 端口 |
| protocol_version | 1 | RBK3.4 为 1，RBK3.5 为 2 |
| rate_hz | 20.0 | 速度发送定时器频率 |
| command_timeout | 0.25 | 最近接收速度超过该秒数后发送零速度 |
| socket_timeout | 0.2 | TCP 操作超时，单位秒 |
| duration_ms | 300 | 底盘单条速度有效时长 |
| max_linear_speed | 0.2 | 平面速度向量模长上限，m/s |
| max_angular_speed | 0.5 | 角速度绝对值上限，rad/s |

这些是本实现选取的初始参数，可通过 `--ros-args -p 参数:=值` 修改。浮点参数使用 `20.0` 这样的浮点写法。

桥接使用深度 1、可靠、易失 QoS。由一个速度发布源控制 `/cmd_vel`。Twist 没有时间戳，超时依据本机单调时钟记录的接收时间。实际停转延迟包括接收超时、定时调度、网络交互及底盘减速时间。

桥接在第一条速度到来前保持等待。开始控制后，正常情况下持续刷新速度或零速度。TCP 或 API 出错时，节点结束并尝试发送零速度，重新运行后等待新的速度消息。

## 5. 后续接入动捕闭环

```text
动捕当前位姿 + 同一世界坐标系下的目标位姿
                    ↓
位姿闭环控制节点
                    ↓ /cmd_vel
本次提供的 TCP 桥接节点
                    ↓ API 2010
底盘
```

假设底盘可以独立控制 vx、vy、w。动捕刚体需要标定到机器人控制参考点，目标位姿和当前位姿应统一坐标系、单位和朝向定义。得到当前位置 `(x,y,theta)` 和目标 `(xg,yg,thetag)` 后，先把位置误差旋转到机器人坐标系

```text
ex =  cos(theta) * (xg-x) + sin(theta) * (yg-y)
ey = -sin(theta) * (xg-x) + cos(theta) * (yg-y)
e_theta = atan2(sin(thetag-theta), cos(thetag-theta))

vx = kp_xy * ex
vy = kp_xy * ey
w  = kp_yaw * e_theta
```

后续控制节点加入速度与加速度限制、动捕失效停车、到位容差和稳定时间判定。位置和朝向误差均连续满足容差后发布零速度并报告到位。精度由动捕标定、时延、底盘低速性能及控制参数共同决定，需要实机测量。

这套闭环可覆盖空旷场地的点到点移动。有障碍物的路径还需要路径规划与避障输入。
